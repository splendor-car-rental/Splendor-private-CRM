# تدقيق مطابقة المستندات الرسمية

## المصدر المعتمد
المرجع الرسمي للهيدليتر هو الملف الذي سلّمه مالك النظام بتاريخ 2026-09-01 بعنوان `SPLENDOR_Letter head.pdf`.

### مواصفات مرجعية مؤكدة من النموذج
- صفحة A4 واحدة.
- رأس صفحة رسمي أسود مع عناصر الهوية البصرية لسـبلندر.
- الاسم الإنجليزي `SPLENDOR CAR RENTAL` والاسم العربي `لتأجير السيارات`.
- العبارة `Prestige Beyond Limits` والعبارة العربية `هيبة بلا حدود`.
- صورة دبي/الإمارات ضمن الرأس.
- مساحة بيضاء واسعة لمحتوى المستند.
- شريط سفلي أحمر يتضمن بيانات التواصل والموقع والحسابات الاجتماعية.
- المحتوى يجب أن يُطبع داخل المساحة البيضاء دون تغطية الرأس أو الفوتر.

## قاعدة التنفيذ
الهيدليتر الرسمي أصل ثابت غير قابل لإعادة الرسم أو إعادة التصميم أو تغيير نصوصه أو أرقامه. يجب استخدام الأصل نفسه عند توفره بصيغة قابلة للإدراج في محرك المستندات.

## الختم
الختم الأحمر الرسمي موجود بالفعل كأصل مستقل في `src/server/assets/splendorStampAsset.ts`. يوضع فقط عند موضع الاعتماد/التوقيع الذي يتطلبه النموذج، ولا يُكرر تلقائيًا في مواضع لا يقتضيها المستند.

## حالة الدمج
- واجهة الهيدليتر المشتركة موجودة في `OfficialLetterheadLayout`.
- مسار الهيدليتر الخاص بمستندات LTO يحتوي حاليًا على PNG placeholder بحجم 1×1، ولذلك لا يُعتبر مطابقًا للنموذج الرسمي حتى استبداله بالأصل الحقيقي.
- تم استلام النموذج الرسمي كملف PDF داخل جلسة العمل الحالية، وتم تثبيت مواصفاته كمرجع تدقيق.
- أداة GitHub الحالية لا توفر مسارًا لنقل مرفق ثنائي من المحادثة مباشرة إلى مستودع GitHub؛ لذلك لم يتم اختلاق نسخة بديلة ولم يتم استبدال الأصل باستخدام إعادة رسم.

## خطة المطابقة
1. حصر جميع قوالب ومستندات الطباعة الفعلية.
2. تحديد مصدر الهيدليتر لكل مستند.
3. استبدال أي placeholder أو هيدليتر مرسوم يدويًا بالأصل الرسمي نفسه.
4. توحيد موضع الختم وفق النموذج المعتمد.
5. اختبار A4 وRTL والهوامش وتعدد الصفحات وعدم تداخل الختم مع النص.
6. إضافة اختبارات تمنع عودة placeholder أو تغيير الأصل المعتمد.

## الاستثناءات
لا تُعتبر المستندات مطابقة نهائيًا بمجرد نجاح البناء؛ المطابقة النهائية تتطلب معاينة PDF الناتج ومقارنته بالنموذج الرسمي.
